# Выкатка RePrep одной командой

## Статус

**Подготовлено локально; на VM не выполнялось.** SSH по указанию владельца больше не диагностируется. Четыре отказа из предыдущего отчёта — намеренно сломанные fixtures теста публикации, а не найденные на VM дефекты. В боевом Compose уже были DEMO_ENABLED=false/APP_ENV=production, в Dockerfile — сборка клиента, в Caddy — отсутствие запрещающего iframe заголовка. Недостающий шаг — автоматический управляемый порядок выкатки и регистрации MAX.

## После восстановления доступа

Из корня проекта (локальная .env уже заполнена):

```sh
.venv/bin/python scripts/deploy_vm.py --apply
```

Без `--apply` команда делает только локальную подготовку и не ходит в SSH/MAX. Предусловия на VM: root по известному ключу, Docker с Compose, активный Caddy и Python3. Их наличие проверяется до передачи релиза; отсутствие — явный блокер, установку/замену общесерверных компонентов этот скрипт не выполняет. Наличие Docker на VM пока не подтверждено. Адрес и порт по умолчанию: reprep.2-26-49-28.nip.io и loopback 8020; занятый чужим сервисом порт отклоняется.

Команда проверяет секреты/Compose, передаёт только разрешённые исходники в новый /opt/reprep/releases/ID; .env и необязательный CA bundle — отдельно. На VM строит Docker-образ с npm build и проверкой index.html, получает ID через MAX GET /me, включает receiver/outbound, принудительно отключает демо и сохраняет ограничение AI на синтетику. Затем запускает контейнер с healthcheck и restart unless-stopped, включает автозапуск Docker/Caddy, добавляет свой site через отдельный Caddy import с validate перед reload. При отказе validate/reload прежняя конфигурация восстанавливается. Чужие сайты и подписки MAX не удаляются.

После HTTPS-проверок регистрирует webhook через POST /subscriptions и проверяет URL/типы через GET /subscriptions. При повторной выкатке тот же URL обновляется с актуальным secret. Неудачные HTTP-проверки не дают зарегистрировать подписку. В конце проверки повторяются с Mac; только после их успеха команда заканчивается готовым URL. Живой вход MAX и учебный AI-сценарий этим не доказаны; ограничения допустимых данных не изменены.

## Повторный предполётный тест на VM

```sh
cd -P /opt/reprep/current
REPREP_RELEASE="$(basename "$PWD")" REPREP_BIND_PORT=8020 docker compose -f infra/vm/compose.yaml exec -T app python -m apps.server.deployment preflight
```

Выдаёт «Готов к публикации: технические проверки пройдены» либо перечень блокеров с ненулевым exit code. Проверяет публичный HTML и его JS-файлы, readiness, iframe/CSP, закрытые демо/анонимный доступ/.env, отклонение поддельных login/webhook, конфигурацию production, ID бота и фактическую подписку MAX. Реальный MAX-вход/доставка события от пользователя и AI остаются отдельным живым прогоном.

С Mac без ключей: `.venv/bin/python scripts/check_public.py --url https://reprep.2-26-49-28.nip.io --human` — HTTP/TLS-часть, не проверяет регистрацию через API.

## Проверено и ограничения

- Локальная подготовка/упаковка и Compose config — прошли.
- Docker image собран; изолированный контейнер без сети/секретов: production, 9 проверок через TestClient — прошли. Настоящий Caddy/TLS в этом тесте отсутствует.
- 40 целевых тестов: MAX, регистрация/read-back на поддельном API, упаковка без env/data, публичные HTTP-проверки и повреждённые fixtures — прошли, включая итоговую предполётную команду.
- Шаблон Caddy прошёл `caddy validate` в изолированном контейнере Caddy 2.11.4 без сети. Это проверка конфигурации, не выдача сертификата.
- Полный удалённый сценарий, сертификат, Caddy reload, автозапуск после реальной перезагрузки и MAX API этой выкатки **не проверены**.
- При ошибке после запуска контейнера автоматического отката версии приложения/БД нет: команда сообщает отказ, сохраняет release и данные. При регистрации подписки и последующей ошибке read-back подписка могла сохраниться; повторная выкатка обновляет тот же URL. Команда не объявляет успех в обоих случаях.
- У общей VM могут быть изменения соседней сессии: выполняется проверка изменения Caddy перед записью, но глобальной блокировки всех внешних редакторов нет. Отдельный lock защищает только две выкатки RePrep.

Официальная семантика: [MAX POST subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions), [MAX GET subscriptions](https://dev.max.ru/docs-api/methods/GET/subscriptions).
