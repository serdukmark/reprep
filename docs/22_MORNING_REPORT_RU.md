## Что реально работает

- Создать черновик с числом, выбором или коротким объяснением; эталон, критерии, навык и подсказка преподавателя; назначить конкретному ученику. После назначения содержание фиксируется, для изменения создаётся копия.
- Ученик сохраняет ответы на сервер по кнопке, восстанавливает после перезагрузки, отправляет окончательную попытку. При сетевом отказе текст не исчезает; уход с несохранённым текстом требует подтверждения. Оригинал сдачи сохраняется неизменным.
- Постоянная очередь получает **настоящий** структурированный разбор через OpenRouter. Внешние ошибки и невалидный JSON оставляют работу доступной преподавателю; нет ложного «проверено».
- Преподаватель подтверждает разбор, исправляет результат/обратную связь, возвращает на новую попытку или отклоняет без обновления прогресса. До решения преподавателя ученик не получает эталоны и сырой AI-ответ.
- Карта навыков ученика и преподавателя строится на подтверждённых свидетельствах; есть экспорт JSON. Неопределённость не учитывается как неверный ответ. Источник отмечается как подтверждённый AI или проверка преподавателя.
- Расписание, HTTPS-ссылки на материалы, личные ручные отметки об оплате. Ученик не видит отметки преподавателя об оплате. Создание и отзыв одноразовых приглашений; принятие/срок/повторное использование проверены API-тестами.
- Вход в демо по роли, изоляция учебных связей и преподавателей, ограниченные сессии, ошибки с reference ID, сброс только демо-данных. HMAC MAX проверен синтетическими тестами; сам MAX ещё не подключён.

## Как посмотреть

На уже настроенном проекте:

```sh
cd /Users/pozitiv4500/Goool/Max_fuck_you
docker compose up --build -d
```

Открыть **http://127.0.0.1:8000**. На экране — «Я преподаватель» / «Я ученик», пометка синтетического демо. Существующий .env не перезаписывать. Команда работает при свободном порте 8000. К завершению проверки локальный Compose уже запущен на этом адресе: один контейнер, около 42 MiB RAM в замере простоя, лимит 384 MiB и 1 CPU. Предыдущие тестовые серверы остановлены.

Демо за 3–5 минут: преподаватель назначает Саше новую работу → в отдельной вкладке ученик отвечает и отправляет → преподаватель открывает разбор и **читает его** → подтверждает или исправляет → ученик повторно открывает работу и «Мой прогресс». Автоматическая кнопка подтверждения не является заменой проверки качества.

Запуск без Docker и команды проверки описаны в [README](../README.md). Для сброса: настройки демо-преподавателя → «Восстановить демо»; это завершает демо-сессии. Для остановки контейнера: `docker compose stop`, данные остаются в volume.

## Что не сделано и почему

1. **Публичный MAX-бот, привязка домена, деплой и уведомления:** ночью запрещены внешние действия; нужен согласованный доступ/домен. Локальный браузер не закрывает этот пункт кейса.
2. **Пилот с преподавателем и учениками:** нужны человек, предметный эталон и порядок обработки данных. Внешний AI для настоящего пользователя заблокирован по умолчанию.
3. **Надёжная автоматическая оценка всех решений:** модели ошибаются и непоследовательны даже на шести русских примерах. Подробности, в том числе неудачные прогоны, не скрыты; прогресс меняет преподаватель.
4. **Презентация PDF/отправка пакета:** нет подтверждённых пилотных результатов и внешнего адреса. Финальная презентация не должна утверждать их существование. Подготовлены технические основания, README, Docker, lock и API-манифест.
5. **Загрузка файлов/OCR, RAG, бот-напоминания, автоплатежи, видео, маркетплейс:** не входят в реализованный узкий P0; файлы/напоминания остаются P1, marketplace/эквайринг — вне текущего scope.
6. **Полный жизненный цикл реальных данных:** нет пользовательского удаления аккаунта, согласий, установленного retention и фоновой очистки. Поэтому реальные данные не разрешены.

## Заглушки, ограничения и то, что придётся менять

- Демо-идентичности и исходная работа — синтетические fixtures. Это явно написано на экране. Настоящий OpenRouter в проверенных живых сценариях **не заглушка**.
- Без ключа запускаются простые LocalRules: числа/выбор по эталону, ограниченная проверка текста. UI прямо называет этот режим проверкой по эталонам, не нейросетью.
- Математические навыки и метки задаёт преподаватель. «Карта навыков» — история оценённых ответов, не психометрическая модель и не прогноз балла ЕГЭ.
- SQLite, одна роль на аккаунт, одна публикация на конкретную учебную связь, максимум 100 работ в текущем списке UI, polling очереди — ускорения для демо. Для роста нужны pagination UI, миграции, отдельная БД/очередь, мониторинг и резервное копирование.
- Ограничение очереди 50 AI-попыток/UTC-день — по числу запросов, не по списанным рублям; отдельные исследовательские скрипты имеют собственный явный запуск. В разборе до 6000 выходных токенов: длинная работа может перейти в ручную проверку.
- Журнал аудита фиксирует действия, не тексты/секреты. Сообщения об ошибочной обратной связи сохраняются в БД; административной панели разбора пока нет, никому автоматически не отправляются.
- Сохранение ответов явное, не autosave. Переходы преподавателя с формой задания защищены; полная история старых попыток в БД есть, отдельного экрана архива попыток пока нет.
- MAX Bridge, нативный back, safe-area/тема MAX не подключены. Перед внешним запуском нужен reverse proxy с ограничением размера тела запроса, TLS и проверкой заголовков доверенного proxy.
