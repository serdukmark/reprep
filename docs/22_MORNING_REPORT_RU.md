### Слабые места для недоброжелательного жюри

- Реальный MAX ещё не пройден; локальная подпись не доказывает интеграцию.
- AI ошибся на двух из шести эталонных синтетических задач; нет независимой оценки на ЕГЭ. Генерация даёт простые и иногда слишком направляющие задания.
- SQLite с одним worker, ограниченные выборки до 100/500/1000 записей; нагрузочный предел не измерен. Длинная проверка задерживает следующую, ручная проверка остаётся доступна.
- Каталог не проверяет квалификацию, группы не создают видео, ручная отметка оплаты не означает перевод денег. LocalRules без ключа явно обозначен как проверка по эталону, не нейросеть.
- Библиотека коллег копирует задания, не предоставляет совместное ведение учеников. Граф знаний вводит преподаватель, это не автоматическая диагностика освоения.
- Отзывы сохраняются, службы модерации/срочных оповещений нет. Напоминания могут повториться при потере сетевого подтверждения MAX.
- Экспорт/удаление проверены на временных БД. Retention, резервные и независимые общие копии требуют политики; авария передачи экспорта может оставить временный файл.
- PDF для ревью, не финальный комплект: нет постоянного HTTPS, команды/контакта, замороженного релиза, внешнего пилота и факта отправки организаторам.

Далее — история предыдущих проверок, не текущий список ограничений. Актуальные статусы выше и в checklist имеют приоритет.

## Что реально работает

- Создать черновик с числом, выбором или коротким объяснением; эталон, критерии, навык и подсказка преподавателя; назначить конкретному ученику. После назначения содержание фиксируется, для изменения создаётся копия.
- Ученик сохраняет ответы на сервер по кнопке, восстанавливает после перезагрузки, отправляет окончательную попытку. При сетевом отказе текст не исчезает; уход с несохранённым текстом требует подтверждения. Оригинал сдачи сохраняется неизменным.
- Постоянная очередь получает **настоящий** структурированный разбор через OpenRouter. Внешние ошибки и невалидный JSON оставляют работу доступной преподавателю; нет ложного «проверено».
- Преподаватель подтверждает разбор, исправляет результат/обратную связь, возвращает на новую попытку или отклоняет без обновления прогресса. До решения преподавателя ученик не получает эталоны и сырой AI-ответ.
- Карта навыков ученика и преподавателя строится на подтверждённых свидетельствах; есть экспорт JSON. Неопределённость не учитывается как неверный ответ. Источник отмечается как подтверждённый AI или проверка преподавателя.
- Расписание, HTTPS-ссылки на материалы, личные ручные отметки об оплате. Ученик не видит отметки преподавателя об оплате. Создание и отзыв одноразовых приглашений; принятие/срок/повторное использование проверены API-тестами.
- Вход в демо по роли, изоляция учебных связей и преподавателей, ограниченные сессии, ошибки с reference ID, сброс только демо-данных. MAX-авторизация и webhook проверены синтетически; настоящий MAX ещё не подключён.

1. **Публичный MAX-бот, привязка домена, деплой и уведомления:** ночью запрещены внешние действия; нужен согласованный доступ/домен. Локальный браузер не закрывает этот пункт кейса.
2. **Пилот с преподавателем и учениками:** нужны человек, предметный эталон и порядок обработки данных. Внешний AI для настоящего пользователя заблокирован по умолчанию.
3. **Надёжная автоматическая оценка всех решений:** модели ошибаются и непоследовательны даже на шести русских примерах. Подробности, в том числе неудачные прогоны, не скрыты; прогресс меняет преподаватель.
4. **Презентация PDF/отправка пакета:** нет подтверждённых пилотных результатов и внешнего адреса. Финальная презентация не должна утверждать их существование. Подготовлены технические основания, README, Docker, lock и API-манифест.
5. **Загрузка файлов/OCR, RAG, бот-напоминания, автоплатежи, видео, маркетплейс:** не входят в реализованный узкий P0; файлы/напоминания остаются P1, marketplace/эквайринг — вне текущего scope.
6. **Полный жизненный цикл реальных данных:** нет пользовательского удаления аккаунта, согласий, установленного retention и фоновой очистки. Поэтому реальные данные не разрешены.

## Заглушки, ограничения и то, что придётся менять

- Демо-идентичности и исходная работа — синтетические fixtures. Это явно написано на экране. Настоящий OpenRouter в проверенных живых сценариях **не заглушка**.
- Без ключа запускаются простые LocalRules: числа/выбор по эталону, ограниченная проверка текста. UI прямо называет этот режим проверкой по эталонам, не нейросетью.
- Математические навыки и метки задаёт преподаватель. «Карта навыков» — история оценённых ответов, не психометрическая модель и не прогноз балла ЕГЭ.
- SQLite, одна роль на аккаунт, одна публикация на конкретную учебную связь, максимум 100 работ в текущем списке UI, polling очереди — ускорения для демо. Для роста нужны pagination UI, миграции, отдельная БД/очередь, мониторинг и резервное копирование.
- Ограничение очереди 50 AI-попыток/UTC-день — по числу запросов, не по списанным рублям; отдельные исследовательские скрипты имеют собственный явный запуск. В разборе до 6000 выходных токенов: длинная работа может перейти в ручную проверку.
- Журнал аудита фиксирует действия, не тексты/секреты. Сообщения об ошибочной обратной связи сохраняются в БД; административной панели разбора пока нет, никому автоматически не отправляются.
- Сохранение ответов явное, не autosave. Переходы преподавателя с формой задания защищены; история отправленных попыток теперь доступна в работе; это просмотр без редактирования старых ответов.
- MAX Bridge/back/closing confirmation и CSS safe-area реализованы и локально симулированы. Нативная тема и фактическое поведение на устройствах MAX не проверены. Reverse proxy/TLS пока только пример конфигурации, не развёрнутая инфраструктура.

## Слабые места глазами недоброжелательного жюри

| Что попробуют / спросят | Честный результат и граница |
|---|---|
| «Откройте это в MAX прямо сейчас» | Главный незакрытый пункт: реального токена/HTTPS и внешнего прогона нет. Локальный iframe его не заменяет. Утренние действия собраны в N-01 |
| «Дайте другой русский пример» | Qwen совпала с агентским эталоном в 4/6 последнего прогона. Нельзя обещать точную автоматическую оценку; нужна предметная проверка эксперта |
| «Отключим OpenRouter» | Контролируемые отказы и ручной цикл проверены. Live-отказ настоящей сети не воспроизводился, DNS/TLS остаются внешним риском |
| «Эта зелёная оценка доказана AI?» | Нет: прогресс означает решение преподавателя. LocalRules и синтетические аккаунты — демонстрационные режимы, не внешний AI/пилот |
| «Вставим огромное решение» | На API лимит тела 150 KB, по ответу 5000 символов, у AI 60 KB контекста. Допустимый длинный оригинал сохраняется для человека; сверх API-лимита сдача отклоняется, текст должен остаться у клиента |
| «Покажите фото тетради / файл / видео» | Не реализованы. Есть текст/число/выбор и HTTPS-ссылки на материалы. OCR, загрузка файлов и видеоконференции не заявлять |
| «Создадим 101 работу» | API имеет offset, текущий список UI показывает до 100. Для большого пилота нужен интерфейс пагинации |
| «Запустим сотню учеников или забьём диск» | Проверены только две одновременные сдачи и небольшая конкуренция чтений. SQLite, один worker, disk-full/аварийное восстановление не испытаны |
| «Убьём процесс после вызова модели» | Очередь постоянная с lease, но возможен повтор платного вызова. Отмена coroutine не убивает зависший поток адаптера; требуется процессная изоляция для длительной эксплуатации |
| «Вернём ответ на запрос слишком поздно» | Клиент ждёт до 15 с, затем предупреждает о неопределённом результате. Сдача идемпотентна; другие создания могут продублироваться при ручном повторе — сначала обновить данные |
| «Есть настоящие пользователи и эффект?» | Нет подтверждённого пилота, согласий и оценки экономии времени. Не выдавать автотесты за пользовательские результаты |
| «Удалите все мои данные / оплатите автоматически» | Полный lifecycle данных и эквайринг отсутствуют. Оплаты только ручные приватные отметки репетитора |

При проверке API найдено, что преподаватель мог получить несданный черновик (UI его не показывал). Доступ сужен: черновик только ученику, преподавателю — отправленная попытка. Это обратимое решение о приватности, записано в реестре; API-тест приватности и полный набор из 47 серверных тестов прошли. После изменений обычные три браузерных сценария (сдача, повторная попытка, обвязка) повторно прошли за 16.6 с; MAX на этом этапе не перепроверялся.
