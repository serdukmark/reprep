# Утро: актуальная первая страница — 22.09.2026

**Адрес MiniApp:** https://reprep.2-26-49-28.nip.io/

## Что сделать владельцу

1. Вставить URL в кабинет бота. Инфраструктура и подписка уже настроены; повторно выкатывать для этого не нужно.
2. Два коллеги с MAX выбирают роли преподавателя и ученика. Живой MAX-прогон ждёт этого действия и ещё не подтверждён.
3. Визуальный показ провести вручную: назначение → ответ ученика → разбор → подтверждение → прогресс. Учесть прежние ограничения AI для реальных аккаунтов; они не отключались. Публичные демо-входы закрыты.

## Что доказано

- Постоянный HTTPS, сертификат, сохранённая подписка MAX, отклонение подделок; Docker/Caddy enabled, RePrep восстановился после перезапуска Docker. Полный reboot-тест самого RePrep не выполнялся.
- Полный **API**, а не визуальный, прогон на публичном стенде: 51 шаг / 12,78 с, настоящий Qwen / 7,14 с. Исправление от роли преподавателя, прогресс, изоляция родителей/коллег и отзыв двух сессий. Синтетика, сессии отозваны.
- Дополнительный HTTPS-прогон восстановления после потерянного ответа: 1,051 с; конфликт 409 и сохранённый черновик. Без нового вызова AI.
- 145 серверных тестов; 13 мутаций обработчика отказов обнаружены. Пустой/медленный AI проверялся изолированно, а не поломкой общего стенда.

## Чего нет

Ручная визуальная репетиция, живой MAX, независимый преподаватель/пилот, история версий опубликованного задания, доказанный холодный build <5 минут, финальная сдача. В checklist 8 завышенных отметок исправлены на «Н». Вопросы платежей/видео/календаря/совместной проверки/универсального AI и политики данных отложены владельцем; они не разрабатывались в этом ходе.

## Проверка и обслуживание

Снаружи: `.venv/bin/python scripts/check_public.py --url https://reprep.2-26-49-28.nip.io --human`.
На VM: `docker exec reprep-app-1 python -m apps.server.deployment preflight`.
Локальное демо для отдельной ручной репетиции: `bash scripts/demo.sh --prepared`, http://127.0.0.1:8000. Оно не заменяет MAX и не является боевым аккаунтом.

RePrep: **127.0.0.1:8030**, общий Caddy: **80/443**, соседние **8010/8020** не трогать. На Mac встречался DNS timeout; прямой HTTPS с сохранением TLS и публичный DNS подтверждали исправность стенда. Не менять сеть ради проверки автоматически.
