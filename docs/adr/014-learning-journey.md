# ADR-014: Серия сдач и путь по подтверждённым навыкам

- Status: accepted for reversible local implementation; rollout not authorized
- Date: 2026-09-30
- Owners: владелец поручил реализацию через Jarvis; правила v1 выбраны агентом в пределах поручения
- Related open questions: OQ-JOURNEY-001/002/003
- Related requirement IDs: FR-PROG-001/002/004/006/007, FR-SUB-002/003/004/005

## Context

[CONFIRMED] Владелец поручил перенести механику макета: честные серверные числа,
SVG вместо эмодзи, скрываемые дополнения, без push/выкатки. Контрольная версия
стенда и архива — f66cf6f. style.css и базовое оформление ведёт другая сессия.

[CONFIRMED, inspected before implementation] В f66cf6f уже есть сроки работ,
время и номер каждой отправки, неизменные оригиналы и история повторных попыток,
reviews и подтверждённые evidence, сводка correct/total/latest и граф предпосылок
преподавателя (ADR-011). Серии и недельного агрегата не было. Цели «4 из 4» как
полнота учебной программы в данных отсутствуют. Макет не является источником чисел.

## Decision

[CONFIRMED scope / ASSUMPTION rules v1] Добавить read-only запрос
`GET /api/relationships/{id}/learning-journey`. Авторизация существующей учебной
связи на сервере; чужие пользователи и родители доступа не получают. Ответ содержит
агрегаты без ответов, эталонов, имён и исходных работ. Без миграции БД.

### Серия v1

1. Отдельно для каждой связи репетитор–ученик; все опубликованные работы, без
   ограничения списка интерфейса в 100 элементов. Единица — работа, не задача.
2. Первая отправка (`attempt=1`) по серверному времени. `submitted <= due_at`
   добавляет 1; при равенстве сдача своевременная. Сравниваются абсолютные моменты
   с часовыми поясами. Сохранение черновика не является отправкой.
3. Порядок — дедлайны. Дедлайн прошёл без своевременной первой сдачи — серия
   обнуляется, даже если пользователь не открывал приложение. Поздняя сдача не
   восстанавливает пропущенный срок.
4. Будущая несданная работа нейтральна: рост приостановлен без обнуления.
   Отправленная заранее уже засчитывается. Нет штрафов за дни без назначений,
   частичных очков или замедляющих коэффициентов.
5. Одинаковые дедлайны — группа. Пропуск любой работы обнуляет группу; иначе
   каждая своевременная сдача добавляет 1. Результат не зависит от порядка ID.
6. Черновики и явное отсутствие срока (`due_at=null`) исключены. Повторные
   попытки, возврат/отклонение, качество ответа и ожидание проверки не изменяют
   факт первой сдачи и не добавляют очки. Серия — факт отправки, не оценка.
7. Нет решившихся событий — `count=null`, пустое состояние. Есть пропуск —
   честный `0`. Повреждённая дата, отсутствующая политика срока/первая попытка
   или сдача в будущем дают `insufficient_data`, без числа серии и награды;
   клиент также скрывает неполные недельные числа.
8. Опубликованная преподавателем работа с уже истёкшим сроком участвует на
   общих основаниях. Освобождений/отмены/переноса в модели нет. Ограничение v1
   оставлено явно в OQ-JOURNEY-002; сроки и историю ради серии не переписываем.

Причина: неизменные факты, воспроизводимые правила, отсутствие штрафа за скорость
преподавателя, ошибки AI, повторную доработку и отсутствие назначений.

### Неделя

Понедельник 00:00 UTC включительно — следующий понедельник исключительно.
Пояс явно написан в UI: настройки учебного пояса в продукте нет. Знаменатель —
опубликованные работы со сроком внутри интервала. `submitted` — наличие первой
сдачи, `on_time` — её своевременность. Награда «Все работы недели сданы» только
при `total>0 && submitted==total` и полных данных. Поздняя сдача входит в эту
награду, но не становится своевременной. Новые назначения могут изменить
сводку; это не вечный сохранённый бейдж и не оценка знаний.

### Мой путь

Использовать граф преподавателя и проверенные результаты. Последний `correct`
даёт галочку «Последняя проверка: верно»; остальные узлы доступны к тренировке
при подтверждённых предпосылках либо показывают замок с их списком. Замок
информационный: назначенные работы доступны. Ветки не соединяются выдуманными
связями. `correct/total` — результаты проверенных задач, не процент освоения.
Без графа — список из проверенной истории; без истории — пустое состояние.
AI-черновик не открывает узлы. Доказательства доступны по выбору навыка.

При включённом `LEARNING_JOURNEY_ENABLED` исправлена потеря evidence у регистровых вариантов одного навыка: сервер графа
суммирует историю без учёта регистра и выбирает последний результат по
`created DESC, id DESC`. Узлы дополнены `evidence_ids` для точной связи со
снимком доказательств. Контракт и группировка старого `/progress` не меняются.
При выключенном флаге сохраняются прежние расчёты и форма ответа `/skill-graph`;
`evidence_ids` является необязательным свойством схемы. Это уточнение от 30.09
сохраняет поведение сдачи `0b7f17b` до разрешённого включения механики.

### Ответы и отправка

Полоса считает заполненные задания текущего черновика: непустой текст либо TXT.
Это ввод, не правильность и не подтверждение сохранения. Остаётся существующая
форма со всеми заданиями, автосохранением, конфликтами версий и файлами.

«Отправлено» появляется после успешного POST submit. Если дальнейшее обновление
экрана не получилось, подтверждение сохраняется, повторный ввод блокируется до
обновления данных. Отказ недельной сводки не меняет факт отправки. Возврат
преподавателем вновь открывает существующий сценарий новой попытки.

## Alternatives considered

- Браузерный подсчёт по списку: неполная история и зависимость от клиента. Отклонено.
- Изменяемый счётчик в БД: миграция/пересчёт/фоновая просрочка без необходимости.
- Цели из макета или освоение по AI: неподтверждённые числа, отклонено.
- Полный пошаговый мастер: отдельная работа с большим риском для сохранения/файлов.

## Consequences

- Product: дополнение к P0, без новых учебных запретов и оценок.
- Engineering: новый GET и поле `learning_journey_enabled` в config; отдельные
  компоненты/CSS без собственных цветовых токенов; API обратно совместим.
- Data/security/privacy: без миграции, новых персональных данных и внешних вызовов.
- Testing: границы сроков/недель, попытки, права, ошибки, >100 работ; browser P0,
  отключение, сетевые отказы, 320 px и скриншоты.
- Operations: `LEARNING_JOURNEY_ENABLED=false` по умолчанию. Для включения локально
  перезапустить сервер и обновить страницу. Push/стенд/архив не затрагивать.
- Documentation: требования, решение, открытые вопросы и локальный отчёт обновлены.

## Validation and rollback

Проверки и воспроизведение — `docs/44_LEARNING_JOURNEY_RU.md`. Выключить флаг:
старые экраны сохраняются, новый GET возвращает 404. Очистка БД не нужна.
Локальная проверка не является релизом; инженерное ревью обязательно.
