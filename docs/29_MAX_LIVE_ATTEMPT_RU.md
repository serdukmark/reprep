# MAX: реальная проверка API и временного HTTPS — 21.09.2026

**Сквозной запуск внутри MAX не выполнен.** Токен и публичный HTTPS больше не являются техническими блокерами. Остался доступ к авторизованному клиенту MAX и настройкам MiniApp: инструменты управления компьютером вернули пустой список браузеров/приложений; создание вкладки через iab и chrome вернуло Browser is not available. Подменять это ещё одной симуляцией не стали.

## Работает и проверено

- token.txt первым действием добавлен в .gitignore, дополнительно исключён из Docker context. В индексе и истории Git файла нет. Значение перенесено в MAX_BOT_TOKEN в .env (600), .env.example содержит пустую переменную. Файл владельца сохранён. Сканер проверяет и значение из token.txt, и факт его попадания в Git.
- Реальный GET https://platform-api2.max.ru/me: HTTP 200, бот t792_hakaton_max_bot. Токен не печатался и не передавался в URL.
- Стандартный TLS-контекст не доверял цепочке API. Корневой сертификат получен по HTTPS из официального источника https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer и добавлен только в SSL-контекст MaxAPI через MAX_CA_BUNDLE. ОС/браузерное доверие не менялось; verify=False не использовалось.
- Локальный сертификат: artifacts/max-ca.pem, SHA256 PEM-файла 936a43fea6e8e525bcc0f81acd9c3d21b4fc4b9b68acea7906d698005afc6504. Это публичный CA, не секрет. Для Docker путь должен быть смонтирован отдельно; абсолютный путь macOS внутри контейнера не работает.
- Официальный cloudflared 2026.9.1 скачан из cloudflare/cloudflared GitHub Releases, хранится в artifacts/tools. Быстрый туннель работал исключительно к 127.0.0.1:8002.
- Отдельный сервер использовал artifacts/max-live-test.sqlite3, синтетические fixtures. Внешний AI был выключен на сетевой проверке; платных вызовов не делали. Рабочая база локального Docker не публиковалась.
- Через публичный HTTPS: /api/health → 200, webhook с поддельным секретом → 401, вход с поддельным initData → 401.
- Настоящий MAX POST /subscriptions вернул success=true; GET /subscriptions подтвердил точный URL. До проверки подписок было 0, после снятия временной подписки снова 0.

## Не проверено

- Реальная доставка события MAX и ответ бота: входящих событий 0. Регистрация webhook не доказывает доставку.
- Привязка URL MiniApp в кабинете партнёра, открытие MiniApp в MAX, реальные initData и их подпись: нет авторизованного клиентского запуска. Созданных недемо-идентичностей 0.
- Полный сценарий двух ролей и живого AI **внутри MAX**, мобильный и web MAX.

## После проверки

Временная подписка удалена через официальный DELETE /subscriptions с точным URL; проверено отсутствие подписок. Туннель и отдельный uvicorn остановлены. PUBLIC_BASE_URL и MAX_CA_BUNDLE очищены в .env, чтобы случайный запуск не использовал протухший домен или путь CA хоста внутри Docker. MAX_BOT_TOKEN и проверенный MAX_BOT_ID сохранены локально; включение бота/исходящих ответов по умолчанию осталось выключенным. Локальное демо на 8000 продолжает работать.

## Что нужно владельцу для следующей попытки

1. Подключить к этой сессии управляемый браузер с авторизованным MAX и доступом к настройкам t792_hakaton_max_bot. Указать тестовые аккаунты ролей; не передавать пароли/коды в Git или отчёт.
2. В согласованное время вновь поднять кратковременный туннель на отдельный синтетический сервер. Новый адрес записать в PUBLIC_BASE_URL, CA указать через MAX_CA_BUNDLE только для этого запуска. Код адреса не содержит.
3. В кабинете MAX: Чат-боты → нужный бот → Настройки → ссылка MiniApp = новый HTTPS origin → сохранить. Затем зарегистрировать webhook, /app, открыть MiniApp и пройти сценарий. Токен Bot API не заменяет доступ к этому кабинету.
4. После проверки снять только нашу подписку и остановить туннель. Если адрес быстро меняется, сохранённая ссылка MiniApp также требует обновления в кабинете; одной переменной приложения для настроек платформы недостаточно.

Официальные основания: [подключение и смена URL MiniApp](https://dev.max.ru/docs/webapps/introduction), [требования API/TLS](https://dev.max.ru/docs-api), [удаление временной подписки](https://dev.max.ru/docs-api/methods/DELETE/subscriptions).
