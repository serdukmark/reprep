## Решение и подготовленные файлы

Владелец разрешил Docker-развёртывание RePrep на личной VM с существующим lct-gaz-gaz. Выбран кандидат `https://reprep.2-26-49-28.nip.io/`: DNS привязан к IP, адрес не меняется после перезапуска приложения. Зависит от сохранения IP и внешнего nip.io; это не собственный домен и пока не опубликованный сервис. [DNS и сертификаты nip.io](https://nip.io/), [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

`infra/vm/compose.yaml` — отдельный Compose project reprep, отдельный volume, loopback-порт обязателен через REPREP_BIND_PORT, restart unless-stopped, лимиты CPU/RAM и журналов. Публичные демо-входы отключены, ограничения передачи данных AI сохранены. `infra/vm/Caddyfile.example` — отдельный virtual host, без запрета MAX iframe. Существующую конфигурацию Caddy заменять нельзя.

## После восстановления SSH

1. Проверить Docker/Compose, занятые порты и имена, текущие Caddy/systemd, свободное место. Кандидат порта 8020 использовать только после проверки. Снять baseline существующего сервиса; не перезагружать общую VM для проверки автозапуска.
2. Секрет-сканер локально; передать код отдельным релизом под /opt/reprep без .git, token.txt, локальной БД и артефактов. Передать .env отдельно по SSH с правами 0600. PUBLIC_BASE_URL задаётся выбранным origin; секреты не выводить. Новая база без реальных учебных данных.
3. Собрать Docker на VM. Выполнить получение bot ID через существующий MaxAPI GET /me без вывода тела/токена, сохранить настройки бота; применить env пересозданием контейнера. Проверить /api/ready локально. Скрипты setup_max не включены в runtime Dockerfile: запускать через отдельное подключение scripts в /app/scripts, а .env через защищённый mount только для setup; не считать их встроенными в image.
4. Добавить отдельный site в существующий Caddy с резервной копией; caddy validate перед reload. Проверить enable Docker и Caddy, restart policy контейнера. Не менять чужие virtual hosts. При ошибке вернуть только своё изменение.
5. Проверить снаружи TLS без отключения верификации, HTML/assets, /api/ready, отсутствие выдачи /.env, неверную MAX initData и webhook secret. Затем зарегистрировать webhook настоящим MAX API и прочитать подписки для подтверждения URL, не печатая secret.
6. Проверить перезапуск своего контейнера и сохранение данных; baseline чужого сервиса должен остаться исправен. Только после этого выдать рабочий URL MiniApp владельцу.
