# Изоляция аккаунтов: углублённая проверка 24.09.2026

Проверки только в loopback headless браузере на синтетической базе. Боевой стенд не изменялся. Это не подтверждение живой смены аккаунтов внутри MAX.

## Причины и общие границы

1. AUD022: успешные ответы запросов предыдущего аккаунта применялись после смены пользователя. Все JSON-запросы клиента проходят через `apps/client/src/api.ts`; там ответ сверяется с версией сессии. Версия меняется в setToken. Проверка стоит до возврата данных вызывающему коду. Отдельный fetch экспорта имеет такую же проверку перед созданием файла.
2. При logout корневой App очищает списки работ, отношений, уроков, материалов, прогресса и приглашений, текущую работу и выбор. Дочерние компоненты размонтируются при переходе к экрану входа.
3. AUD025 (этот проход): корневые буферы `inviteInput` и `alias` переживали logout. Новый ученик видел введённый предыдущим код приглашения; форма регистрации MAX/TG показывала прежнее имя. Красные UI-прогоны подтверждают оба случая. Очистка дополнена, также сбрасываются роль регистрации, toast, режим редактирования, меню, текущий раздел и ссылка на незавершённое копирование. Это обратимое исправление приватности, дополнительных денег/доступов не нужно.

| Область | Где хранится | Граница изоляции | Проверка |
|---|---|---|---|

| Имя регистрации и непринятый код | App | Явная очистка буферов при logout | auth previous registration alias MAX/TG; session-caches unaccepted invitation |
| Экспорт аккаунта | Отдельный fetch/blob | Версия сессии до URL/скачивания | account-switch delayed export; мутация AUD022 выявлена |
| TXT материалов и ICS | api, затем blob | Общая проверка версии; обработчик принадлежит старому компоненту | session-downloads: 2/2 прошли; отключение общей защиты обнаружено обоими тестами |
| TXT ответа | Синхронное скачивание из уже открытой работы | Компонент работы размонтируется; уже скачанный файл не отзывается | Файлы/история проверены ранее; это не обещание удалить начатый до logout download |
| Группы, пространства коллег, анкета каталога, план, граф | Локальный state дочерних компонентов | Размонтирование + запросы api от новой сессии | session-screens: запись старым преподавателем, logout, другой преподаватель, повторное открытие/reload |

| Напоминания | Notifications, сервер по user_id | Размонтирование + индивидуальные предпочтения | session-screens notification: настройки нового преподавателя не наследуются, включая reload |
| Хранилище браузера | Только sessionStorage для токена | setToken очищает ключ; при запрете storage токен в памяти | auth/max существующие тесты; в клиенте не найдены localStorage, IndexedDB, Cache API для пользовательских данных |

- session-caches-before: 1 failed (код приглашения), 4 passed. Затем тесты отношений/расписания усилены: количество учебных связей и отдельный урок другого ученика, а не только отсутствие кнопок преподавателя.
- registration-cache-before: 2 failed, имя осталось в MAX и Telegram.
- session-isolation-after: 34 passed, включая существующие проверки AUD022, вход/выход/отказы, 5 session-caches и 7 session-screens.
- После этого session-screens усилен ожиданием ответов новой сессии; добавлены родитель и напоминания. Все 9 прошли в session-screens-confirmed.
- session-isolation-mutation: все 7 тестов обнаружили намеренно отключённые защиты.
- session-downloads-after: 2/2 прошли; mutation: 2/2 обнаружили выдачу файла старого аккаунта.
