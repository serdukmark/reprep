Актуализировано 20.09.2026. Это техническая сверка, не подтверждение организатором соответствия готового продукта.

## Командный контекст

Изучен топик «Образовательные решения MAX» чата ЛЦТ через предоставленный Telegram-скрипт: 172 сообщения за 15 августа — 19 сентября и приложенные материалы. Ключевая идея — пространство для независимого репетитора и его учеников, где AI встроен в проверку и учитывает подтверждённую историю по навыкам. Голосовая идея 15 августа шире: расписание, материалы, оплаты, рекомендации других репетиторов и AI-репетитор. Для текущего P0 сохранён узкий учебный цикл; маркетплейс и эквайринг не добавлялись.

Командные обсуждения — продуктовый контекст. Они не заменяют документацию MAX, правила организатора или согласие на обработку данных.

## Официальный кейс

Сохранён [PDF «Образовательные решения», 22 страницы](official/education-case.pdf), полученный из топика команды.

- Решение — бот MAX либо бот с MiniApp, работоспособность на мобильном и web.
- Образовательные направления описаны широко; обязательность реализовать одновременно навыки, карьеру и безопасность не установлена. Фокус на репетиторе — наша продуктовая интерпретация, а не отдельное разрешение организатора.
- Оценка онлайн: продукт 40%, техническая часть 60%. Полезная дополнительная возможность MAX может дать бонус 0.15; наличие своего API само по себе бонусом не является.
- Docker обязателен, сборка до 5 минут без времени загрузки базовых образов.
- Артефакты: работающий MAX, исходный код с commit hash, README, зафиксированные зависимости, PDF-презентация. Для собственного API — HTTPS, OpenAPI3, тестовые данные/идентичности, DATA-API.yaml.
- Известная дата сдачи — 30 сентября; точное время/форма и финальные требования к доступу уточняются командой.

В текущей ветке локальная техника проверена, внешний MAX и отправка пакета не выполнены. Утренние действия — N-01/N-03 в реестре вопросов.

## MAX: что реализовано по документации

[Официальная проверка initData](https://dev.max.ru/docs/webapps/validation): параметры WebAppData из URL-фрагмента декодируются, hash исключается, остальные пары сортируются и соединяются переводом строки. Ключ HMAC-SHA256 выводится из токена бота и константы WebAppData; полученная подпись сверяется с hash. В reprep проверка выполняется сервером, дубли параметров отклоняются, сравнение timing-safe. Дополнительно установлен наш TTL 300 секунд и допуск будущего времени 30 секунд. После входа выдаётся собственная ограниченная по сроку сессия; токен бота остаётся серверным.

Клиент передаёт сырые параметры запуска на /api/auth/max и не доверяет role/id из неподписанных полей. Роль впервые выбирается при онбординге; при повторном входе существующая роль не заменяется клиентом.

[MAX Bridge](https://dev.max.ru/docs/webapps/bridge) предоставляет window.WebApp и методы взаимодействия с клиентом. Текущий интерфейс использует документированные параметры URL, но Bridge пока не подключён: нативный back, safe-area, тема, полноэкранное поведение и возможный MAX-бонус требуют отдельной реальной проверки.

Для проверки авторизации есть синтетические тесты Unicode, срока и подмены подписи. Это не равнозначно запуску в настоящем MAX. Бот-уведомления, автоматическая отправка приглашений и регистрация webhook не реализованы; ночью внешние сообщения запрещены владельцем.
