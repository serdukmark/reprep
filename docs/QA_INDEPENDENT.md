- Код: ветка `feat/reprep-mvp`, HEAD `4a6249d` (24.09 01:12). Во время прогона автор параллельно правил `ChoiceSelect.tsx` и браузерные тесты без коммита, и `dist/` пересобирался. Хеш бандла снимка `index-CBogZKNO.js` совпадает с тем, что отдаёт `https://reprep.ru/`, то есть проверялась ровно выкачанная версия.
- Четыре изолированных экземпляра из этого снимка, у каждого своя временная SQLite в `/tmp`. `.env` не читался (переменные обнулены), в сеть ничего не уходило:
  - `:8771` — демо + проверка по эталонам (`LocalRules`), как локальное демо без ключа;
  - `:8772` — демо + поддельная «модель» под моим управлением. Режимы: успех / отказ / мусорный JSON / HTML и длинный текст в ответе / ответ дольше 60 с. Подкласс `OpenRouterAdapter`, чтобы включились вопросы и генерация;
  - `:8773` — как на стенде: `APP_ENV=production`, демо выключено, вход через MAX с синтетическим токеном бота. `initData` подписывала сама по алгоритму `auth.verify_max`;
  - `:8774` — то же + поддельная модель: что видят настоящие (не демо) пользователи при подключённом AI.
- Браузер: Chrome в headless-режиме через Playwright, отдельный процесс, экраны 1440×1000 и 390×844. Окна владельца не трогались. Запросы к `st.max.ru`/`telegram.org` в тестах MAX блокировались.
- Публичный стенд `reprep.ru` — только GET без входа: health/config, заголовки, анонимный доступ. POST не отправлялись, чтобы не расходовать общий лимит входа (см. QA-04).

Строгость: **Критично** — ломает основной сценарий или раскрывает чужие данные. **Высокая** — заявленная функция не работает. **Средняя** — работает неверно или вводит в заблуждение. **Низкая** — неудобство, косметика.

### QA-04. Высокая (по коду и конфигурации; на стенде намеренно не воспроизводилось). Лимит входа 30 в минуту, вероятно, общий для всех пользователей стенда

Где: `apps/server/main.py:332-341` — ключ лимита `request.client.host`. `Dockerfile:20` — `uvicorn` без `--forwarded-allow-ips`. `infra/vm/compose.yaml` — порт опубликован как `127.0.0.1:${REPREP_BIND_PORT}:8000`, перед ним Caddy (`infra/vm/Caddyfile.example`). В `uvicorn 0.53.0` по умолчанию доверенные прокси — только `127.0.0.1,::1`. Контейнер видит соединение не с `127.0.0.1`, а с адреса Docker-сети, поэтому `X-Forwarded-For` от Caddy игнорируется и у всех пользователей одинаковый `client.host`.

Что воспроизвела локально (`:8773`): 30 неудачных `POST /api/auth/max` с одного адреса, затем корректно подписанный вход другого человека с того же адреса → **429** «Слишком много попыток. Подождите минуту».
Следствие на стенде: каждое открытие мини-приложения — это вход (`sessionStorage` не переживает запуск). Класс из 30 учеников, одновременно открывший приложение, или одна сломанная интеграция, повторяющая вход, блокирует вход всем на минуту. Проверить на стенде можно только перебором входов, а это заблокировало бы живых пользователей, поэтому не проверяла. Проверить без вреда владелец может так: `docker exec reprep-app-1 python -c "…"` с печатью `request.client.host` или логом одного запроса.

## 9. Как воспроизвести мои прогоны

Скрипты лежат вне репозитория (`/tmp/reprep-qa`) и в Git не попадают. Суть обвязки, если понадобится повторить:

```python
# harness.py — изолированный экземпляр из снимка HEAD, без .env и сети
import os, sys
for k in ('OPENROUTER_API_KEY','OPENROUTER_MODEL','MAX_BOT_TOKEN','TELEGRAM_BOT_TOKEN','AI_ADAPTER_URL','AI_ADAPTER_KEY','PUBLIC_BASE_URL','MAX_WEBHOOK_SECRET'):
    os.environ[k] = ''
sys.path.insert(0, '/tmp/reprep-qa/src')          # git archive 4a6249d | tar -x
from apps.server.config import Settings
from apps.server.main import create_app
app = create_app(Settings(database='/tmp/reprep-qa/qa.sqlite3', environment='development', demo=True))
# «как стенд»: Settings(environment='production', demo=False, bot_token='<синтетический>')
# поддельная модель: подкласс OpenRouterAdapter с analyze/answer_question/generate_assignment без сети
```

Подпись `initData` для входа «из MAX»: `secret = HMAC_SHA256(key=b"WebAppData", msg=bot_token)`, `hash = HMAC_SHA256(secret, "\n".join(sorted("k=v")))`. Открыть `/#WebAppData=<urlencoded initData>`, запросы к `st.max.ru` заблокировать.
